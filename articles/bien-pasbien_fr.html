Appliquer des principes de clean code

✅ GRASP : General Responsibility Assignment Software Patterns
  1. Information Expert — attribuer la responsabilité à la classe qui a l'information nécessaire
  2. Creator — la classe qui crée un objet
  3. Controller — gérer les événements du système
  4. Low Coupling — minimiser les dépendances entre classes (encapsulation)
  5. High Cohesion — une classe doit avoir une responsabilité bien ciblée
  6. Polymorphism — utiliser le polymorphisme pour gérer les variations
  7. Pure Fabrication — créer des classes artificielles pour éviter le couplage fort ou les responsabilités qui n'appartiennent pas aux classes de domaine
  8. Indirection — utiliser une classe intermédiaire pour réduire les dépendances
  9. Protected Variations — protéger les éléments instables derrière des interfaces ou abstractions

🧐 Bien / Pas Bien

❌ Pas Bien

Nommer ses variables en abrégé ou sans signification concrète

❌ Magic Number
JavaScript let ThirtyOne = 31;
Python ThirtyOne = 31
C# using System; class Program { static void Main() { int ThirtyOne = 31; } }

❌ Pas Bien

Ne pas permettre de rollback en cas de crash avant le commit dans la base de données

✅ ACID : Atomicity

Si la première requête passe et que le serveur plante avant la deuxième :

  • Le compte [id = 1] est débité
  • Le compte [id = 2] n'est pas crédité

➡️ Argent perdu

SQL UPDATE comptes SET solde = solde - 100 WHERE id = 1; -- Panne serveur ici, ou crash de l’appli UPDATE comptes SET solde = solde + 100 WHERE id = 2;

❌ Pas Bien

Dupliquer du code au lieu de factoriser

✅ DRY : Don't Repeat Yourself
JavaScript console.log("Hello world"); console.log("Hello Jack"); console.log("Hello John");
Python print("Hello world") print("Hello Jack") print("Hello John")
C# Console.WriteLine("Hello world"); Console.WriteLine("Hello Jack"); Console.WriteLine("Hello John");

✅ Bien

Documenter son code et le rendre intuitif

✅ KISS : Keep It Simple Stupid
JavaScript function calculerTVA(prixHT) { // Calcule la TVA pour un prix HT return prixHT * 0.2; }
Python def calculer_tva(prix_ht): """Calcule la TVA pour un prix HT""" return prix_ht * 0.2
C# public double CalculerTVA(double prixHT) { // Calcule la TVA pour un prix HT return prixHT * 0.2; }

❌ Pas Bien

Trop de logique dans une seule fonction/classe

✅ SRP : Single Responsibility Principle (SOLID)
JavaScript function processUserData() { // Lire les données // Valider les données // Calculer des trucs // Générer un rapport // Envoyer un mail ... }
Python def process_user_data(): # Lire les données # Valider les données # Calculer des trucs # Générer un rapport # Envoyer un mail ...
C# public void ProcessUserData() { // Lire les données // Valider les données // Calculer des trucs // Générer un rapport // Envoyer un mail ... }

✅ Bien

Appliquer des principes de clean code

✅ GRASP : General Responsibility Assignment Software Patterns
  1. Information Expert — attribuer la responsabilité à la classe qui a l'information nécessaire
  2. Creator — la classe qui crée un objet
  3. Controller — gérer les événements du système
  4. Low Coupling — minimiser les dépendances entre classes (encapsulation)
  5. High Cohesion — une classe doit avoir une responsabilité bien ciblée
  6. Polymorphism — utiliser le polymorphisme pour gérer les variations
  7. Pure Fabrication — créer des classes artificielles pour éviter le couplage fort ou les responsabilités qui n'appartiennent pas aux classes de domaine
  8. Indirection — utiliser une classe intermédiaire pour réduire les dépendances
  9. Protected Variations — protéger les éléments instables derrière des interfaces ou abstractions

❌ Pas Bien

Ne pas respecter les contraintes de la base de données avant et après transaction

✅ ACID : Consistency
SQL CREATE TABLE comptes ( id INTEGER PRIMARY KEY, solde INTEGER ); -- Un solde négatif ne pas être autorisé dans un contexte bancaire BEGIN; UPDATE comptes SET solde = solde - 200 WHERE id = 1; COMMIT;

✅ Bien

Capturer les erreurs

✅ Fail Fast
JavaScript function divideNumbers(dividend, divisor) { try { if (divisor === 0) { throw new Error("Division by zero is not allowed"); } const result = dividend / divisor; return result; } catch (error) { return null; } finally { console.log("Request succeeded"); } }
Python def divide_numbers(dividend, divisor): try: if divisor == 0: raise ValueError("Division by zero is not allowed") result = dividend / divisor return result except ValueError as error: return None finally: print("Request succeeded")
C# static double DivideNumbers(double dividend, double divisor) { try { if (divisor == 0) { throw new ArgumentException("Division by zero is not allowed"); } double result = dividend / divisor; return result; } catch (ArgumentException error) { return double.NaN; } finally { Console.WriteLine("Request succeeded"); } }

❌ Pas Bien

Modification du code existant au lieu de l'étendre

✅ OCP : Open/Closed Principle (SOLID)
JavaScript function calculerPrix(panier, typeClient) { if (typeClient === "pro") { return panier * 0.9; } else if (typeClient === "vip") { return panier * 0.8; } else { return panier; } }
Python def calculer_prix(panier, type_client): if type_client == "pro": return panier * 0.9 elif type_client == "vip": return panier * 0.8
C# public static double CalculerPrix(double panier, string typeClient) { if (typeClient == "pro") { return panier * 0.9; } else if (typeClient == "vip") { return panier * 0.8; } else { return panier; } }

✅ Bien

Ne pas hériter une classe qui ne respecte pas le contrat ou comportement attendu de la classe mère

✅ LSP : Liskov Substitution Principle (SOLID)
JavaScript class Client { calculerPrix(panier) { return panier; } } class ClientPro extends Client { calculerPrix(panier) { return panier * 0.9; } } class ClientVip extends Client { calculerPrix(panier) { return panier * 0.8; } } [ new Client(), new ClientPro(), new ClientVip() ] .forEach(c => console.log(c.calculerPrix(100)));
Python class Client: def calculer_prix(self, panier): return panier class ClientPro(Client): def calculer_prix(self, panier): return panier * 0.9 class ClientVip(Client): def calculer_prix(self, panier): return panier * 0.8 for client in [Client(), ClientPro(), ClientVip()]: print(client.calculer_prix(100))
C# using System; class Client { public virtual double CalculerPrix(double panier) => panier; } class ClientPro : Client { public override double CalculerPrix(double panier) => panier * 0.9; } class ClientVip : Client { public override double CalculerPrix(double panier) => panier * 0.8; } class Program { static void Main() { Client[] clients = { new Client(), new ClientPro(), new ClientVip() }; foreach (var c in clients) Console.WriteLine(c.CalculerPrix(100)); } }

❌ Pas Bien

Interface/Classe trop conséquente imposée à tout le monde

✅ ISP : Interface Segregation Principle (SOLID)
JavaScript class Animal { eat() { } fly() { } } class Cat extends Animal { fly() { // Inutile pour un chat } }
Python class Animal: def eat(self): pass def fly(self): pass class Cat(Animal): def fly(self): # Inutile pour un chat pass
C# public abstract class Animal { public abstract void Eat(); public abstract void Fly(); } /* public interface IAnimal { void Eat(); void Fly(); } */ public class Cat : Animal { public override void Eat() { // Mange normalement Console.WriteLine("Cat is eating"); } public void Fly() { // Inutile pour un chat mais doit être implémentée } }

✅ Bien

Le modèle stocke les données, la vue les affiche et le contrôleur les crée

✅ MVC : Model View Controller
C# using System; using System.Collections.Generic; // Model class TaskModel { public List<string> Tasks = new List<string>(); public void AddTask(string task) { Tasks.Add(task); } public List<string> GetAll() { return Tasks; } } // View class TaskView { public static void Display(List<string> tasks) { for (int i = 0; i < tasks.Count; i++) { Console.WriteLine($"{i+1}. {tasks[i]}"); } } } // Controller class TaskController { private TaskModel model; private TaskView view; public TaskController(TaskModel m, TaskView v) { model = m; view = v; } public void AddNewTask(string task) { model.AddTask(task); TaskView.Display(model.GetAll()); } }

❌ Pas Bien

Permettre des "dirty reads" (lecture de données non validées), "non-repeatable reads" (relecture de données modifiées par une autre transaction), "phantom reads" (nouvelles lignes apparaissant dans une requête répétée)

✅ ACID : Isolation
SQL -- Transaction 1 BEGIN; SELECT solde FROM comptes WHERE id=1; -- lit 100 UPDATE comptes SET solde = solde - 80 WHERE id=1; -- Pas encore de commit -- Transaction 2 (concurente) BEGIN; SELECT solde FROM comptes WHERE id=1; -- lit aussi 100 UPDATE comptes SET solde = solde - 80 WHERE id=1; COMMIT; -- Transaction 1 commit après, écrase modification de T2 COMMIT;

✅ Bien

Une fonction ne doit parler qu'à ses proches (elle-même, ses attributs directs, les objets qu’on lui passe, les objets qu’elle crée)...

✅ LoD : Law of Demeter
JavaScript function getCustomerCity(order) { return order.getCustomerCity(); }
Python def get_customer_city(order): return order.get_customer_city()
C# string GetCustomerCity(Order order) { return order.GetCustomerCity(); }

✅ ACID : Durability
SQL BEGIN TRANSACTION UPDATE comptes SET solde = solde - 100 WHERE id = 1 UPDATE comptes SET solde = solde + 100 WHERE id = 2 COMMIT -- Données validées mais crash serveur avant écriture disque -- Il faut mettre en place un mécanisme comme le Write-Ahead Log (WAL) -- Même si la machine plante juste après, les modifications peuvent être récupérées au redémarrage en relisant ce journal

✅ Bien

Les classes ne doivent pas dépendre d’autres classes mais d’interfaces ou de classes abstraites

✅ DIP : Dependency Inversion Principle (SOLID)
JavaScript class MessageService { send(msg) {} } class EmailService extends MessageService { send(msg) { console.log(msg); } } class OrderManager { constructor(service) { this.service = service; } notify(message) { this.service.send(message); } }
Python class MessageService: def send(self, message): pass class EmailService(MessageService): def send(self, message): print(f"Email envoyé : {message}") class OrderManager: def __init__(self, service): self.service = service def notify(self): self.service.send("Commande confirmée")
C# public interface IMessageService { void Send(string message); } public class EmailService : IMessageService { public void Send(string message) { Console.WriteLine($"Email envoyé : {message}"); } } public class OrderManager { private readonly IMessageService _service; public OrderManager(IMessageService service) { _service = service; } public void Notify() { _service.Send("Commande confirmée"); } }

❌ Pas Bien

Coder maintenant une fonctionnalité qu'on estime utile pour plus tard

YAGNI : You Aren’t Gonna Need It
JavaScript function calculerTotal(prix, tva, remise = 0, primeAnniversaire = 0) { const total = prix + (prix * tva); // Les autres paramètres ne servent à rien pour le moment return total; }
Python def calculer_total(prix, tva, remise=0, prime_anniversaire=0): total = prix + (prix * tva) # Les autres paramètres ne servent pas encore return total
C# public decimal CalculerTotal(decimal prix, decimal tva, decimal remise = 0, decimal primeAnniversaire = 0) { decimal total = prix + (prix * tva); // Les autres paramètres sont inutiles pour le moment return total; }

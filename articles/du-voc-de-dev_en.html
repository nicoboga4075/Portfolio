From the dev vocab
In the software development world, we often cross words like framework, library, package and module... While these words are sometimes, through misuse of language, used as synonyms in technical discussions, they are quite distinct concepts. Each plays a specific role in how developers structure, organize and automate their projects. To better understand these differences, this article provides a clear and accessible overview of these concepts, illustrated through concrete examples such as Angular, Selenium, Numpy and the math module in Python. The goal is to choose the right tool at the right time, based on the needs and context of the project.

Framework

A framework is a complete environment that provides a predefined architecture for developing applications. It imposes rules, conventions and a workflow that the developer must follow. The idea is to standardize development and reduce errors thanks to a rigid structure.

ASP.NET Core (C#)

ASP.NET Core is powerful, flexible and interoperable (Linux, MacOS and Windows), making it an excellent choice for modern development (web applications, APIs or microservices). It supports large-scale and critical applications for large businesses such as Microsoft and is supported by the large Stack Overflow community. Its modular design allows you to choose the components you need and it has robust security features to protect you from common vulnerabilities (OWASP). However, even if .NET has become easier to use, early-stage developers might find it more difficult than the frameworks associated with languages like Python or JavaScript, described below. Since the release of .NET 5 in November 2020, the "Core" has officially disappeared from the name.

Flask (Python)

Flask, used by Netflix, has been known for its ease of use since its inception in 2010. Unlike "battery-included" frameworks like Django used by Instagram, Flask has a minimalist kernel, making it adaptable to a variety of projects, from simple REST APIs to microservices to more complex web applications. This gives developers flexibility but also requires them to make more decisions about architecture and component selection. This can be an advantage for experienced developers but it can be difficult for juniors who are penalized by the lack of built-in features. Furthermore, while Flask adequately addresses common security needs, it requires developers to be more pragmatic in the architecture and security of their applications.

Angular (JavaScript)

Angular, developed by Google, is used to create interactive web applications. Notably, it includes tools for state management, data binding and HTTP requests. You work "in" the framework, which controls the organization and execution of your code (reverse control). This makes it a powerful yet demanding environment in terms of compliance with its conventions. AngularJS has been completely at the end of its lifespan since late 2021 and since 2016, any Angular is native TypeScript.

Library

A library is a collection of reusable classes or functions that you can call to perform specific tasks. Unlike a framework, you control the integration and execution of features.

Newtonsoft.Json (C#)

This is an open-source library for the .NET framework that enables you to serialize (convert an object to JSON) and deserialize (convert JSON to an object) easily.

Selenium (Python)

Selenium is used to automate the testing of web applications, providing functions to interact with browsers, such as clicking buttons or filling out forms.

Moment (JavaScript)

Moment allows manipulation and formatting of dates and times (for example, YYYY-MM-DD).

IronPDF (C#)

IronPDF is specialized in generating, editing and retrieving PDF content.

Numpy (Python)

Numpy is a compelling part of scientific computation, including advanced mathematical functions and tools for manipulating multidimensionalarrays.

jQuery (JavaScript)

jQuery simplifies interaction with the DOM (Document Object Model) and events on web pages.

Package

A package is an organized set of modules, often grouped together in a single folder, that can be used to structure and organize code in a logical, reusable way. It can also contain other packages (subpackages), configuration files and resources. This is a NuGet (.nupkg) for C#, a pip (folder with __init__.py) for Python and a npm (folder with package.json) for JavaScript. For example, the System.Collections.Immutable package in C# provides immutable collections for .NET and the cross-env package in JavaScript allows you to set environment variables in a way that is compatible with all platforms.

Module

A module is the smallest of the four components, so you can import it to perform one-time operations. It has no complex dependencies or imposed structure. It is simply a file containing code (with extension .cs for C#, .py for Python and .js for JavaScript), such as functions or classes that you can import and use. As a reminder, a variable is a named space in memory that stores a value, a function is a reusable block of code that performs a precise action and a class is a template for creating objects that contain attributes ("proprietary" variables) and methods ("behavioral" functions). For instance, the Python math module contains basic mathematical functions, such as sqrt, sin or log.

Understanding these differences is key to choosing the right tool for your needs. Use a framework like Angular if you're looking for an all-in-one solution to structure your project. Prefer a library like Selenium for a specialized task or a Numpy for a scientific field. Finally, modules such as math from Python are perfect for light and one-off needs. By mastering these concepts, you will optimize your approach to development, choosing the right tool for each situation. Below is a summary table to share with your software teams:

  • internal : accessible only in the assembly
  • protected : accessible only in the class and its derivatives
  • private : accessible only in the class
C#
A static class defines utility classes and cannot be instantiated or inherited. All its methods and properties must be static. However, a static method can exist in any class.
C#
A sealed class blocks any inheritance like a static class but is instantiable. A sealed method prevents redefining behavior in derived classes. It therefore never makes sense in a sealed class.
C#
An abstract class or method can be used to create a common model with some already implemented methods, while an interface defines only a contract that different classes can implement, even if they are not inherited. An abstract method can exist only in an abstract class, but an abstract class can contain no abstract method. A class (non-sealed and non-static) can inherit only one other class (non-sealed and non-static), but can implement multiple interfaces to combine different behaviors.
C#
Polymorphism allows the same method to exhibit different behaviors depending on the actual type of the object which uses it.
  • virtual : allows a method to be overridden in a derived class
  • override : used to replace a virtual or abstract method from the base class with a new implementation
  • new : hides an inherited method intentionally without modifying the original
C#
Value types (int, double, float, bool, char, struct, enum) are copied independently and stored on the stack, while reference types (class, string, array, object, delegate) point to the same object in memory and are stored on the heap. Changing a variable (value type) does not affect another, but modifying an object (reference type) impacts all references pointing to that object.
C#
A shallow copy creates a new object but internal objects remain shared with the original. A deep copy creates a new object and also copies all internal objects, making the copy completely independent. In C#, MemberwiseClone() performs a shallow copy, while a custom method or serialization can be used for a deep copy.
C#
A delegate is a type that can hold a reference to one or more methods with the same signature, while a lambda expression is an anonymous inline function written concisely. In C#, a lambda is typed according to the delegate it is assigned to: Action if it returns nothing, Func if it returns a value, Predicate if it returns a boolean or a custom delegate type if defined explicitly (for example delegate int Operation(int a, int b)).
C#
A Thread is a low-level execution unit managed directly by the operating system and started with Start(). A Task is a higher-level abstraction built on the ThreadPool, created and started with Task.Run() and used with async/await. The ThreadPool executes tasks automatically and reuses threads instead of creating new ones for each operation.
C#
The garbage collector automatically manages memory by freeing unreachable objects to prevent memory leaks. It tracks object references and reclaims those no longer used, optimizing performance using a generational system. It does not release unmanaged resources (files, connections...). For those, use Dispose() or a using block to guarantee explicit and immediate cleanup.
SEO (Search Engine Optimization) aims to improve the organic visibility of a site on search engines through backlinks and content/structure optimization, producing durable but gradual results. SEA (Search Engine Advertising) consists of buying paid ads to generate immediate traffic, with fast results that depend on the budget.
B2B (Business to Business) refers to sales between companies (e.g. Salesforce or SAP) with longer, more deliberative purchasing decisions, while B2C (Business to Consumer) targets individual consumers (e.g. Amazon, Zara, Netflix) with faster, often emotional purchases.
The Client-Server model describes communication where a client (e.g. a web browser requesting a page or a mobile app which calls an API) sends requests to obtain data or services from a server. The Server-Server model describes automated exchanges of information between two servers, for example when a web server queries a database server to display content or when an authentication server validates access for another application server.
On-premise refers to a model where servers, softwares and infrastructures are installed and managed directly within the company (office equipment, ERP, SQL or Oracle databases, files), on a local server or a PC rather than in the cloud. The company handles maintenance, security and updates, offering full control but higher costs and responsibilities.
Cloud computing, by contrast, offers service models ("as a Service"). Each model is distinguished by the level of control left to the customer and the degree of management provided by the supplier:
  • SaaS (Software): ready-to-use applications managed by the provider (e.g. Google Drive)
  • PaaS (Platform): an environment to develop and deploy apps (e.g. Netlify, AWS Elastic Beanstalk), in which the developer focus on the code
  • IaaS (Infrastructure): virtualized resources rented to the client (e.g. OVHcloud, AWS EC2)
  • BaaS (Backend): ready-made backend services for web or mobile apps (e.g. Supabase, AWS Amplify)
  • FaaS (Function): execute code on demand without managing servers (e.g. Azure Functions, AWS Lambda)
  • CaaS (Container): container orchestration and deployment (e.g. Azure AKS, AWS ECS)
  • NaaS (Network): on-demand network services (e.g. AWS Direct Connect, AWS Wavelength), without the need to purchase or maintain physical hardware
  • MaaS (Monitoring): monitoring and tracking services for systems, applications and infrastructures (e.g. Datadog)
  • AIaaS (AI): cloud AI services (e.g. OpenAI API, IBM Watson)
  • DBaaS (Database): managed database services for the client (e.g. MongoDB Atlas, Amazon RDS)
  • DEaaS (Desktop): virtual desktop services (e.g. Windows 365, Amazon WorkSpaces)
  • SECaaS (Security): cloud security services (e.g. Cloudflare)
  • BPMaaS (Business Process): platforms for automating, managing and optimizing business processes (e.g. IBM BPM oracle BPM)
  • STaaS (Storage): on-demand storage services with maintenance, backup and scalability management (e.g. Dropbox, Amazon S3)
  • DAaaS (Data Analytics): on-demand analytics services (e.g. Google BigQuery, AWS Redshift)
  • UCaaS (Unified Communication): communication services (e.g. Zoom) such as voice, video, chat or SMS
Cyber
Symmetric encryption (AES for example) is fast but requires sharing a secret key to encrypt and decrypt, while asymmetric encryption (RSA for instance) is more secure because it uses a key pair (public/private) at the cost of lower speed.
Serialization consists of converting an object into a transferable or storable format (JSON, XML, binary), while deserialization does the opposite: it reconstructs the object from that format. In Python, json.dumps(obj) serializes an object to JSON and json.loads(json_str) deserializes it. In C#, JsonSerializer.Serialize(obj) and JsonSerializer.Deserialize(json) do the same thing and in JavaScript, JSON.stringify and JSON.parse respectively do the same.
Frontend is the visible part of a website or application that the user interacts with (buttons, menus, forms), built with HTML, CSS, JavaScript (Vanilla, React, Angular, Vue...) or TypeScript. Backend runs behind the scenes to manage data, business logic and communication with the frontend, using languages such as PHP, Python, C# or Node and databases (SQL Server, PostgreSQL, MongoDB, Elasticsearch...). Together they enable an application to work following the Client-Server model: the frontend displays and receives actions, backend processes and stores information.
Vertical scaling means making a server more powerful by adding CPU, RAM or storage; it's simple but limited by hardware. Horizontal scaling means adding multiple servers to distribute load (load balancing); it's highly scalable and resilient but more complex to manage.
CPU (processor) is the "brain" of the computer or server. It executes instructions, performs calculations and processes data. Its speed and number of hearts determine how many tasks can be executed quickly.
RAM (random-access memory) is the temporary memory where the CPU stores data and programs currently in use. More RAM allows handling more programs or data concurrently, but RAM does not perform computations by itself.
SQL
SQL and NoSQL are two types of databases with different approaches:
  • SQL (Structured Query Language): relational databases organized in tables with relationships (e.g. MySQL, PostgreSQL). Data follows a fixed schema. This is like a well-organized workbook with strict tables and rules in a common language, ideal for applications requiring high consistency and complex relationships.
  • NoSQL (Not Only SQL): non-relational databases, often more flexible and scalable. Data can be stored as documents (MongoDB, Elasticsearch), key-value (Redis), columns (Cassandra) or graphs (Neo4j) without a fixed schema. This is similar to a freer storage box where it is possible to store various documents without a rigid structure, ideal for massive or unstructured data.
SQL
ACID (Atomicity, Consistency, Isolation, Durability) ensures reliable and consistent transactions (e.g. banking or healthcare systems), typical of SQL databases.
BASE (Basically Available, Soft state, Eventually consistent) favors availability, scalability and performance (e.g. a social network or a streaming platform): the system remains accessible, state can change and consistency is achieved eventually, typical of NoSQL systems.
REST (Representational State Transfer) uses multiple endpoints (URLs) to access the data and each query returns a fixed set of information (for example, a restaurant card, where the consumer chooses a menu and then possibly dishes in the latter). This architectural style is simple and widely used to create APIs using HTTP, but it may return too much or too little data (over/under-fetching). GraphQL, on the other hand, uses a single endpoint and allows you to request exactly the fields you need, reducing overload (for instance, a buffet, where the consumer chooses their ingredients only once to fill his plate). This query language, usually using HTTP, is more flexible but more complex to implement.
Both API keys and tokens authenticate and authorize access to an API, but they differ in usage:
  • An API key is a static value often used by applications to identify a client and access fixed resources. It is suitable for automated exchanges on the Server-Server model. It is like a master key that a permanent employee uses to enter a building: it always opens the same doors and remains valid for a long time.
  • A token is dynamically generated after authentication and represents a temporary user session with limited permissions. It is preferred for user logins and controlled access and typically expires after some time. It is like a temporary badge given to a visitor: it allows access only to certain areas for a limited time and then it expires.
A nominal (normal) test verifies that the application works under ideal conditions (e.g. driving on a perfectly paved road with all signs respected). A degraded test checks robustness, resilience and fault tolerance (e.g. driving the same car in rain or snow, on a slippery road or with a flat tire). For example, a nominal test could submit a web form with all fields correctly filled; a degraded test would submit incorrect or missing data to validate error handling.
In FIFO (First In, First Out) structure, the first inserted element is the first processed, like a queue. FIFO is used for request queues, buffers or message queues.
In LIFO (Last In, First Out) structure, the last inserted element is the first processed, like a stack of plates. LIFO is used for the call stack, undo/redo navigation or certain recursive algorithms such as the factorial one.
In Point-to-Point, a producer sends a message to a queue and a single consumer receives it, guaranteeing one-time, reliable processing (e.g. job processing with RabbitMQ Queue or IBM MQ). In Publish/Subscribe, a producer publishes a message to a topic and all subscribers receive it, enabling broadcast of events to multiple consumers (e.g. notifications, real-time streams) using technologies like Kafka, MQTT or Redis Pub/Sub. A broker or hub (ORB) can centralize message management, offering persistence, routing and decoupling between producers and consumers.
An exchange in a message broker acts like a postman that routes messages to the correct queues:
  • Direct: the postman delivers the message exactly to the box with the address matching the routing key
  • Topic: the postman uses pattern-based routing to deliver messages to boxes that match certain categories (wildcards * and #)
  • Fanout: the postman copies the message to all bound boxes, like a broadcast to everyone, no matter the address
A paradigm is a programming style or approach that defines how to organize code, represent data and structure program execution. Each paradigm offers a different way of thinking and organizing a program and the choice depends on the needs for modularity, reusability, responsiveness and maintainability. The main paradigms include:
  • Procedural: organizes code into functions or procedures executed sequentially, such as following a recipe
  • Object-Oriented: structures code around objects combining data and behavior, such as autonomous devices with their own functions
  • Aspect-Oriented: separates cross-cutting concerns (logging, security) from main code, such as an invisible thread that crosses several objects (decorator)
  • Component-Based: builds applications from modular, reusable components, such as Lego modules assembled to create a system
  • Event-Driven: programs react to events (clicks, messages, signals), such as detectors that automatically trigger actions
A design pattern is a documented solution to a recurring object-oriented design problem that can be applied in new contexts. The GoF (Gang of Four) identified 23 patterns in the book "Design Patterns: Elements of Reusable Object-Oriented Software" (1994) by Erich Gamma, Richard Helm, Ralph Johnson and John Vlissides. There are 3 main categories of patterns:
  • Creational: Ways to instantiate objects
    • Singleton: Ensure a class has only one instance (create it if it does not exist, otherwise return it) => In an orchestra, there is only one conductor (the Singleton).
    • Factory: Delegate object creation to subclasses without exposing the instantiation logic => In a restaurant, the customer orders without knowing how the dish is prepared. The chef (the Creator) chooses the right ingredients and method according to the order.
    • Abstract Factory: Provide an interface for creating families of related objects => At restaurant, a menu (the Abstract Factory) offers different meal sets (the Concrete Factories) without exposing preparation details.
    • Builder: Build a complex object step by step => On a construction site, an architect (the Director) defines the plan but the worker (the Builder) decides how to do it.
    • Prototype: Create a new object by cloning an existing one => With a photocopier, it is possible to make a copy (the Clone) of a document (the Prototype).
  • Structural: Composition of classes and objects to form larger structures
    • Adapter: Allow incompatible interfaces to work together => At a conference, if two people (the Adaptees) speak different languages, an interpreter (the Adapter) translates messages so they can understand each other.
    • Bridge: Separate an abstraction (what an object does) from its implementation (how it does it), allowing them to evolve independently => In a car (the Abstraction), the engine (the Implementation) can be diesel, petrol, electric or hybrid without redesigning the whole vehicle.
    • Composite: Treat individual objects and collections uniformly => In a file system (the Component), a folder (the Composite or Container) can contain files (the Leafs) or other folders and the entire hierarchy can be traversed the same way (like a tree).
    • Decorator: Dynamically add responsibilities to an object without modifying its original class => On a car (the Base), you can add a sticker (the Decorator); this does not alter its core function.
    • Facade: Provide a simple and unified interface to a complex subsystem made of many classes, modules or APIs => On the phone, the switchboard (the Facade) centralizes incoming communications so the customer does not need to know each service’s number (the Subsystem) and is automatically redirected.
    • Flyweight: Share objects to save memory when many similar objects are needed => On a chessboard, there are many "black/white pawns" (the Flyweight), but their positions differ.
    • Proxy: Substitute or control access to an object for optimization purposes => A bodyguard or a secretary (the Proxy) protects or assists their boss (the Service).
  • Behavioral: Communication and behavior of objects
    • Observer: Allow an object to automatically notify others when its state changes => On a social network, when a user (the Subject or Observee) posts new content, all followers (the Observers) are automatically notified.
    • Strategy: Dynamically change an algorithm used by an object without modifying its code => In a car, a GPS can change routing strategies: shortest, fastest or avoiding tolls/traffic.
    • Command: Encapsulate a request or action as an object, allowing it to be parameterized, stored, queued or replayed => In the army, an officer (the Invoker) issues an order (the Command). Soldiers (the Receivers) execute it as instructed.
    • Iterator: Access elements of a collection sequentially without exposing its internal structure => The up/down button (the Iterator) on a remote control browses TV channels (the Collection) one by one.
    • Mediator: Centralize communication between objects to reduce direct dependencies => Developers (the Components) report their actions to a project manager (the Mediator) who coordinates decisions and resolves conflicts.
    • Memento: Save and restore an object’s internal state without exposing it => During a VM backup (the Memento or Snapshot), the state is stored by the manager (the Caretaker) for recovery.
    • State: Change an object’s behavior depending on its internal state => A computer (the Context) behaves differently when on, sleeping or powered off.
    • Template: Define an algorithm skeleton while allowing subclasses to customize steps => A newspaper follows a fixed layout, but each editor decides the content.
    • Visitor: Add new operations to object structures without modifying their classes => A tour guide (the Visitor) visits monuments (the Elements) and applies specific actions.
    • Chain of Responsibility: Pass a request along a chain of handlers => A customer calls tech support: level 1 tries, otherwise escalates to level 2, then a supervisor.
    • Interpreter: Define a grammar and interpret expressions => A calculator parses "2 + 3 × 5" using syntax rules and an AST.
A 4th category is sometimes added: Concurrency. These patterns were not explicitly listed in the original book but are useful in multithreaded or distributed systems.
  • Active Object: Delegate an action to an object that executes it asynchronously using queues and threads => A restaurant kitchen workflow with scheduler and notifications.
  • Thread Pool: Reuse a fixed set of threads => Deliveroo couriers reused for multiple deliveries.
  • Future / Promise: Represent a result not yet available => Buying a lottery ticket before the draw.
  • Scheduler / Timer: Execute tasks at specific times or periodically => Microwave timer or electronic calendar.
  • Guarded Suspension: Make a thread wait until a condition is met => A car waiting at a red light.
  • Monitor Object: Encapsulate a shared resource with synchronized access => An ATM serving one client at a time.
An architecture can be defined as the structured organization of a software system, determining how its components interact, communicate and evolve. It serves as a blueprint to design robust, modular and maintainable applications while meeting functional and technical requirements. There are 6 categories:
  • Service/Flow-Oriented: Organize systems around services and events, promoting communication and responsiveness
    • Layered: Separate into layers (presentation, business logic, data) => A restaurant follows a 3-tier architecture: the dining room for customers (UI), the kitchen preparing the dishes (Business) and the pantry storing ingredients (Database).
    • Microservices: Decompose into small independent services (REST), each with a specific responsibility and able to operate, evolve and deploy autonomously => In a fast-food restaurant, burger cooking, fries preparation and counter service each work independently, yet all contribute to the overall service.
    • SOA (Service-Oriented): Decompose into independent and interoperable services (SOAP), each with a precise function and reusable by different applications => A transport company with different vehicles for each type of goods.
    • EDA (Event-Driven): React to events asynchronously => A falling domino triggers a chain reaction.
    • Serverless (FaaS): Execute functions on demand => A technician comes only when needed, performs the work and leaves. You pay nothing when idle.
    • Message-Driven (Queue-Based): Communicate asynchronously via a queue or message broker (RabbitMQ, Kafka, AWS SQS) => At the post office, letters are sorted before reaching the recipient.
  • Component-Oriented: Structure applications in independent modules or extensions, enhancing modularity and maintainability
    • Monolithic: Compact all functionality in a single block => A Swiss army knife contains multiple tools in one object: blade, screwdriver, scissors, file, corkscrew… Practical at first (versatile and portable), but hard to evolve or repair.
    • Modular (Component-Based): Divide into independent, reusable modules within a single deployment => With a kitchen robot, you can swap the mixer, chopper or juicer (the Components) as needed. Similarly, a restaurant menu can have multiple options (lunch, dinner, children).
    • Plug-in: Add extensions to a minimal core => Like a browser with optional extensions, enriching functionality without changing the core.
    • Hexagonal: Isolate the core business logic from dependencies, exchanging everything via interfaces and concrete implementations => The brain makes decisions, nerves (Ports) transmit signals and organs (Adapters) execute actions, while the brain remains unchanged.
  • Model-Oriented: Separate responsibilities for clarity and reusability
    • MVC (Model View Controller): Separate business logic, user interface (observing the model) and interaction management => A theater: the script (Model), the director (Controller) guiding the actors (Endpoints), the performance seen by the audience (View).
    • MVP (Model View Presenter): Variant of MVC with a Presenter managing View logic => In a restaurant, the waiter (Presenter) takes the order, translates it to the chef and delivers the dish. The customer never interacts directly with the kitchen.
    • MVVM (Model View ViewModel): Enable two-way binding between interface and business logic => A remote control (ViewModel) controlling a TV without touching the screen.
    • MVU (Model View Update): Create a repetitive, unidirectional cycle to manage interface and state => In Excel, updates to cell data automatically refresh the display.
    • MDA (Model-Driven): Generate code or system from abstract models => An architect creates plans before building.
  • Domain-Oriented: Focus design on business logic, isolating critical logic and structuring code around functional domains
    • DDD (Domain-Driven Design): Organize software around domain vocabulary and rules => In a library, each section (bounded context) manages a specific domain (logistics, billing…). Books (entities and aggregates) follow rules specific to their section.
    • Onion: Protect the core domain from external layers (frameworks, databases, UIs) => The heart pumps blood and is central, independent from surrounding organs (Adapters).
    • Clean: Strictly isolate dependencies from business logic => A fortress with a treasure in the center and walls for protection.
  • Specialized: Address specific needs like event handling, responsiveness or command-query separation
    • CQRS (Command Query Responsibility Segregation): Separate write operations (commands) and read operations (queries) => In a bank, depositing/withdrawing money (commands) happens at the counter; checking balance (queries) can be done on a screen or app.
    • Event Sourcing: Store all events to reconstruct state => In Git history, you store not only the final code, but all commits. Similarly, a health record keeps all historical data.
    • Chain of Responsibility: Create a sequence of processing steps => In a CI/CD pipeline, each stage (unit tests, integration tests, linting, build) verifies part of the code and blocks or validates to proceed.
    • Reactive: Automatically respond to changes (data, events, load) => The immune system detects threats (viruses, bacteria) and reacts automatically. Similarly, a responsive application adapts to screen sizes and devices while maintaining optimal user experience.
  • Distributed / Cloud: Design scalable, distributed systems optimized for cloud and node communication
    • Client-Server: Centralize service on a server, requested by one or multiple clients => At a pharmacy, the patient (Client) requests medication or information and the pharmacist (Server) provides exactly what is needed.
    • P2P (Peer-to-Peer): Enable direct exchanges between equal nodes => Drivers and passengers coordinate directly, no central server needed.
    • Middleware: Position an intermediary to route messages between applications => A travel agency (Middleware/Broker) organizes bookings from multiple providers.
    • Cloud-Native (12-Factor Apps): Optimize for cloud scalability, resilience and deployment => A pop-up store can be set up quickly anywhere, equipped fully and dismantled without affecting other operations. Each process or microservice behaves independently and can be moved or removed without interrupting the whole system.
Like an application, a component or an object, a service has a lifecycle defining when it is created, how long it stays active and when it is destroyed.
  • Transient: created on each use, such as ordering a takeaway coffee, ideal for stateless services (stateless).
  • Scoped: lives for a specific context (e.g. an HTTP request), such as a daily club subscription used all day.
  • Singleton: a single instance for the application lifetime, similar to a shared family fridge, useful for global resources or expensive to create.

An HTTP request is a message sent by a client (often a browser or application) to a server to request a resource, perform an action or send data. It generally consists of several elements:
  • The URL represents the address of the requested resource => https://api.example.com/users
  • The method indicates the type of action: GET to retrieve a resource, POST to create, PUT to modify, DELETE to remove
  • The headers contain additional information (authentication, content type, language...)
  • The body contains the data sent to the server (often JSON for REST APIs)
  • Parameters allow sending additional information to the request:
    • Query: placed in the URL after a "?" to filter, sort or specify the request => GET https://api.example.com/users?age=25&city=Paris
    • Path / Route: directly included in the URL to identify a resource => GET https://api.example.com/users/123
    • Header: included in headers for authentication, data format or session info => Authorization: Bearer {token} Content-Type: application/json
    • Body: sent in the request body (mainly with POST or PUT) for complex data (JSON, XML, form) => {"name": "Dupont", "email": "dupont@example.com"}
    • Form: used when sending data as an HTML form (application/x-www-form-urlencoded or multipart/form-data)
An HTTP response is the message sent by the server following an HTTP request from a client (browser, app, API...). It indicates the result of the request processing (success, error, redirect...) and may contain data or metadata. It consists of three main parts:
  • The status contains the code and message => HTTP/1.1 200 OK
    Codes are grouped by category:
    • 1xx: informational (rarely used) => 100 Continue
    • 2xx: success => 200 OK, 201 Created, 204 No Content
    • 3xx: redirection => 300 Redirection, 301 Moved Permanently, 302 Moved Temporarily
    • 4xx: client error => 400 Bad Request, 401 Unauthorized, 402 Payment Required, 403 Forbidden, 404 Not Found
    • 5xx: server error => 500 Internal Server Error, 501 Not Implemented, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout
  • The headers provide additional information: content type, response size, cookies, cache management
  • The body contains the data sent by the server (often JSON or HTML) => {"id": 1, "name": "Dupont", "email": "dupont@example.com"}

OWASP (Open Web Application Security Project) is a non-profit organization focused on improving software security. First published in 2003, the Top 10 is a reference document to raise developer awareness about web application security:
  • Broken Access Control: Access control defines which resources a user can view or modify. Mitigation: enforce least privilege, regularly audit servers and websites, remove inactive users/services, use authorization tokens invalidated after logout.
  • Cryptographic Failures: Cryptographic flaws occur when sensitive data is poorly protected during storage or transmission. Causes include absence of encryption (plain passwords in DB), misuse (leak of keys or private certificates) or outdated algorithms (MD5, SHA-1). Mitigation: encrypt all sensitive data, protect keys, renew certificates regularly, use HTTPS and modern algorithms like AES (encryption) or SHA-256 (hashing).
  • Injection: Injection attacks happen when untrusted data is submitted via forms or inputs. Example: SQL injection (SQLi) where an attacker inserts SQL code to manipulate a database. Mitigation: validate and sanitize inputs (required fields, types, whitelists/blacklists), limit actions (permissions, submission frequency, transactions).
  • Insecure Design: Poor design introduces flaws in system logic, e.g., missing login attempt limits (brute-force risk), overly permissive user roles, lack of server-side validation.
  • Security Misconfiguration: Occurs when default settings are left unchanged in sites or CMS. Can affect servers, databases, networks, code, frameworks or containers. Mitigation: change defaults, remove unused components, control visible information, segment architecture, automate configuration management.
  • Vulnerable and Outdated Components: Using frameworks or libraries with known vulnerabilities can expose applications to 0-day attacks. Mitigation: update components, remove unused ones, use trusted sources, employ WAF or IDS.
  • Identification and Authentication Failures: Allows attackers to access user accounts, including admin accounts, often via flaws in authentication or session management, brute-force or social engineering. Mitigation: avoid weak/default passwords, deploy MFA, do not expose session IDs in URLs, manage rotation and expiration. Users must prove their identity.
  • Software and Data Integrity Failures: Unauthorized modification of code or data. Mitigation: use trusted sources, implement integrity checks (hash, checksum), verify digital signatures and updates.
  • Security Logging and Monitoring Failures: Critical activities are not properly logged or monitored, delaying attack detection. Mitigation: alert on privilege escalation, log important events (login, backup, deletion, addition), store securely and auditable.

OSI (Open Systems Interconnection) is a framework describing network system functions (ISO 7498). It categorizes functions of network components and defines rules and requirements to ensure interoperability of software and hardware. The 7-layer model is useful to visualize data flow from sender to receiver. Communication passes from layer 7 to layer 1. Each layer performs a specific task before passing data to the next.
  • Physical: Deals with hardware and transmission medium. Defines how bits (0 and 1) are encoded/transmitted and electrical/optical standards for signals. Examples: cables, radio waves, ports, Wi-Fi, fiber optics.
  • Data Link: Ensures reliable data transfer over a local network. Divides packets into frames, manages media access, error detection/correction. Sub-layers: MAC and LLC. Example: Ethernet.
  • Network: Transfers data between networks and determines optimal routing. Encapsulates segments into packets, uses logical addressing. Examples: IPv4, IPv6.
  • Transport: Provides end-to-end communication. Segments/reassembles data, controls errors, manages flow. Examples: TCP (reliable), UDP (fast, unreliable).
  • Session: Manages opening, synchronization and closing of connections. Establishes checkpoints for interrupted transfers and optimizes resource use. Example: NFS.
  • Presentation: Translates/formats data for application layer. Handles encryption, compression and data format conversion. Examples: JSON, HTML, CSV.
  • Application: Direct user interface. Allows applications (browsers, mail clients) to access network and communicate. Manages data presentation and application protocols. Examples: HTTP, HTTPS, SMTP.
TCP/IP (Transmission Control Protocol/Internet Protocol) is an alternative model to OSI. TCP and IP are separate protocols that together ensure data reaches its intended destination: IP determines the address of the application/device, TCP handles transport and routing. The 4 layers are:
  • Data Link: Combines OSI physical and data link functions, handling frame transmission, signaling, hardware addressing and error control via NICs, Ethernet and Wi-Fi.
  • Internet: Corresponds to OSI network layer. Manages logical addressing (IP), routing between networks, ensures packets reach destination, handles fragmentation/reassembly.
  • Transport: Corresponds to OSI transport layer. Ensures end-to-end communication: segmenting, numbering, reassembling, flow control, error detection/correction, retransmission.
  • Application: Combines OSI session, presentation and application layers. Provides interface between applications and network: allows software/users to send/receive data, manages application protocols, formats data for applications.

The Transformer is a neural network architecture introduced in 2017 ("Attention Is All You Need", Google). It processes an entire sequence in parallel through a self-attention mechanism that weighs, for every token, its relevance to every other token, capturing long-range dependencies without recurrence — unlike RNNs and LSTMs, which are sequential, or CNNs, whose receptive field is local. It stacks encoder and/or decoder blocks (multi-head attention plus feed-forward layers, with residual connections and layer normalisation) and underpins nearly every modern large language model: encoder-only (BERT) for understanding, decoder-only (GPT, Claude) for generation, encoder-decoder (T5) for translation. Because the computation is fully parallel it maps well onto GPUs: training and inference at scale rely almost entirely on NVIDIA hardware — from a single T4 in a notebook to clusters of H100s — through CUDA, NVIDIA’s parallel-computing platform. On top of such models, agent patterns like the ReAct loop (Reason + Act) interleave a reasoning step with a tool call, feed the resulting observation back into the model and repeat until it produces a final answer. To standardise how such agents reach external tools and data, Anthropic released the Model Context Protocol (MCP) in 2024 — an open client–server protocol, quickly adopted across the ecosystem, that exposes tools, resources and prompts to any compatible model. A related pattern, Retrieval-Augmented Generation (RAG), grounds answers by pulling relevant passages from a knowledge base into the prompt rather than by calling a tool.

Nucleus sampling (or top-p) is a decoding strategy for language models. Rather than always taking the most likely next token (greedy) or sampling from the whole vocabulary, it keeps the smallest set of leading tokens whose cumulative probability reaches a threshold p (say 0.9) — the nucleus — renormalises it and samples from there. The candidate pool shrinks when the model is confident and widens when it hesitates, keeping the output varied without letting improbable tokens through. Unlike top-k, which fixes the number of candidates, top-p adapts it; both are usually combined with the temperature.

k-NN (k-Nearest Neighbours) is a lazy, non-parametric algorithm: it stores the training set and, to classify a new point, looks at its k closest points under a distance metric (Euclidean, cosine, Manhattan) and takes the majority vote — or the average, for regression. There is no training phase, so every prediction costs a full scan of the data unless it is indexed (k-d tree, ball tree, HNSW). A small k follows the noise and overfits; a large k oversmooths and blurs class boundaries. For binary classification an odd k is preferable: it rules out a tied vote (with k = 4 the neighbours can split 2–2, with k = 5 they cannot). Features must be scaled first, or the largest-range feature dominates the distance.
